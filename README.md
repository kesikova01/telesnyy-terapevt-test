# Тест для телесного терапевта

Тест по первопричинам (психосоматика) — та же логика и те же вопросы, что на
[тесте по первопричинам](https://kuraylife.vercel.app/), плюс **телесная карта результата**
(взята из теста «К корню»): в конце разбора на схеме тела подсвечиваются зоны,
где чаще всего живёт напряжение при найденном паттерне.

Сайт подстраивается под экран: на телефоне — одна колонка, на планшете — с полями,
на ноутбуке и большом мониторе результат раскладывается в две колонки
(слева разбор, справа телесная карта, цепочка и итог).

Оформление — тёплый терапевтичный стиль: песочный фон, серифные заголовки (Lora),
подписи моноширинным в разрядку (IBM Plex Mono), приглушённый зелёный акцент.
Оранжевым отмечены только зоны напряжения на телесной карте.

Все цвета, шрифты и скругления собраны переменными в начале `src/styles.css` —
чтобы перекрасить сайт, достаточно поменять их там.

## Как запустить

```bash
npm install
npm run dev
```

Дальше открыть http://localhost:5173

Сборка для продакшена: `npm run build` → папка `dist/`.
Посмотреть собранный сайт локально: `node serve.mjs` → http://localhost:5181

### Быстрый показ результата

Адрес с `?demo=1` (например `http://localhost:5173/?demo=1`) сразу открывает экран
результата с демо-анкетой — удобно показывать эксперту, не проходя тест заново.

## Что нужно заполнить перед публикацией

Все настройки в одном файле — `src/config.js`:

| Поле | Что это |
|------|---------|
| `WHATSAPP_NUMBER` | номер WhatsApp эксперта, только цифры (например `77076151515`) |
| `LINK_LESSONS` | ссылка на телеграм-канал с бесплатными уроками |
| `ADMIN_PASSWORD` | пароль от админки (сейчас `telo2026`) |
| `GOOGLE_SHEET_URL` | адрес Apps Script Web App, если анкеты нужно писать в Google Таблицу |
| `SUPABASE_URL` / `SUPABASE_KEY` | доступы к базе, если анкеты нужно хранить в Supabase |

Пока поля пустые — сайт полностью работает, анкеты сохраняются в браузере
и видны в админке. Кнопки «Записаться» и «Бесплатные уроки» становятся активными,
как только заполнены `WHATSAPP_NUMBER` и `LINK_LESSONS`.

## Админка

На первом экране (выбор языка) внизу — иконка замка. Пароль из `ADMIN_PASSWORD`.
Показывает все анкеты, ответы, зоны напряжения и полный текст разбора.

## Структура

```
src/
  App.jsx                 весь тест: шаги, валидация, сборка разбора, админка
  config.js               ссылки и доступы
  styles.css              оформление и переменные цветов
  components/BodyMap.jsx      интерактивная телесная карта (зоны кликабельные, с пульсом)
  components/Insights.jsx     общий вывод, цепочка взаимосвязей, итог, «следующий шаг»
  components/TypingLoader.jsx эффект печатающегося текста на экране загрузки
  components/ShareCard.jsx    карточка для соцсетей — рисуется на canvas, без личных данных
  data/psychoDb.js        тексты разборов (ru/kz) — как в исходном тесте
  data/bodyMap.js         какие зоны подсвечивать под каждый результат
  data/insights.js        описания зон, уточняющие утверждения, формулировки выводов, паттерны
```

## Что показывает экран результата

1. **Общий вывод** — короткий персональный абзац: главный фактор, давность, зоны тела, эмоции.
2. **Полный разбор** — физическая, эмоциональная и ментальная блокировка, вопросы для самоанализа.
3. **Интерактивная телесная карта** — можно нажать на любую зону и прочитать,
   почему она отмечена и с чем это может быть связано.
4. **Основные взаимосвязи** — цепочка «ситуация → эмоции → давность → зоны тела → снижение энергии»,
   собранная из ответов клиента.
5. **Что поддерживает состояние** — то, что клиент отметил на шаге уточнений.
6. **Итог** с дисклеймером: это не диагноз, а анализ ответов.
7. **Следующий шаг** — блок с приглашением на разбор и кнопки записи.
8. **Поделиться результатом** — обезличенная картинка для соцсетей (без имени и телефона):
   телесная карта и название паттерна. Кнопка использует Web Share API на телефоне
   (открывает системное меню «Поделиться») и скачивание PNG на компьютере.

Шаг 9 «Уточним детали» — четыре утверждения со шкалой «Да / Иногда / Нет».
Первое утверждение подбирается под сферу клиента (тексты в `src/data/insights.js`),
остальные общие. Ответ «Да» на общее утверждение добавляет свою зону на телесную карту:
трудно расслабиться → плечи, сон не восстанавливает → челюсть, не на кого опереться → поясница.

Перед кнопками записи — персональная строка «Ваш паттерн: …», использующая
найденный паттерн клиента, а не общий призыв. Экран загрузки печатает фразы по буквам
(в третьей упоминается реально найденная зона), а блоки результата появляются
по очереди, а не все разом — это создаёт ощущение живого, а не шаблонного анализа.

## Тёмная тема

Кнопка-переключатель (значок луны/солнца) видна на каждом экране в правом верхнем углу.
По умолчанию сайт подстраивается под системную тему устройства; если человек переключил
вручную — выбор запоминается в браузере. Все цвета берутся из тех же переменных
в `src/styles.css`, поэтому тёмная тема не требует отдельной вёрстки экранов.

## Как устроена телесная карта

`App.jsx` подбирает блок разбора по ключевым словам из ответа про здоровье
(кожа → `skin`, голова → `head`, спина → `back`, ЖКТ → `stomach`, женское → `women`),
а если совпадений нет — по сфере отношений / денег / самооценки.
Полученный ключ передаётся в `BodyMap`, который берёт из `data/bodyMap.js`
две зоны (первая — сильное напряжение, вторая — слабое) и подпись под схемой.

Чтобы поменять зоны или текст — править только `src/data/bodyMap.js`.

Слова сравниваются по основе, а не буква в букву: «мигрени», «мигрень», «мигренью»
попадают в один блок. В исходном тесте поиск шёл по точной подстроке, поэтому
«частые мигрени» не находились и разбор уходил в другую сферу.

## Чтобы сайт не слетел

Сделано четыре запаса прочности — сайт не зависит от одной точки отказа:

1. **Версии библиотек зафиксированы точно** (без `^`), плюс `package-lock.json`.
   Через год `npm install` поставит ровно те же версии, что работают сейчас,
   и обновление какой-нибудь библиотеки не сломает сборку.
2. **Готовая сборка лежит в репозитории** — папка `static-build/`.
   Это обычные html, css и js: их можно перетащить на любой хостинг
   (Netlify, Beget, хостинг эксперта) и сайт заработает без установки чего-либо.
   Обновить копию: `npm run backup`.
3. **Автопубликация на GitHub Pages** — файл `.github/workflows/deploy.yml` готов,
   но ещё не залит: у токена GitHub нет права `workflow`. Чтобы включить запасную площадку,
   выполните `gh auth refresh -h github.com -s workflow` и скажите — я загружу файл.
   После этого при каждом изменении GitHub будет сам собирать сайт, и рабочая копия
   останется по адресу https://kesikova01.github.io/telesnyy-terapevt-test/
   даже если Vercel отключится.
4. **Относительные пути к файлам** (`base: './'` в `vite.config.js`) —
   сайт одинаково работает на своём домене, во вложенной папке и открытый прямо с диска.

Версия Node записана в `.nvmrc` (20) — на ней проект точно собирается.

## Чего пока нет из ТЗ эксперта

Живого AI (языковой модели), который сам придумывает вопросы и пишет текст разбора.
Для этого нужны ключ API, серверная функция-прокси на Vercel (ключ нельзя держать в коде сайта)
и оплата за каждый разбор. Сейчас вопросы и выводы собираются из ответов клиента по правилам —
без ключей, без оплаты и без риска, что модель придумает лишнее в медицинской теме.
